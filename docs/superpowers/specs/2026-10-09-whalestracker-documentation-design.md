# Дизайн: полная документация WhalesTracker для рерайта

Дата: 2026-10-09
Статус: согласован подход A (слоевой обход с параллельными субагентами)

## Цель

Создать в `docs/` репозитория максимально полную документацию **текущей** системы WhalesTracker (MERN TDS, код ~2021 г.) как источник правды для полного переписывания проекта. Документация описывает, что система делает СЕГОДНЯ, а не что должна делать.

## Не-цели

- Не исправляем код, не обновляем зависимости, не рефакторим.
- Не проектируем новую систему (это отдельный цикл после рерайта).
- Не переносим документацию с netlify — сверяемся с ней как с контрольным списком.

## Метод выполнения

1. **Фаза 1 (параллельные субагенты):** независимые исследования слоёв — (а) бэкенд-ядро, (б) API-роуты, (в) домен+трекер, (г) фронтенд-страницы, (д) API-клиент фронтенда. Каждый возвращает структурированные находки.
2. **Фаза 2 (я сам):** сборка шести MD-документов из находок, сверка полноты.
3. **Фаза 3:** обход netlify-документации (все ~20 страниц) и сверка с кодом → `06-docs-vs-code.md`.
4. **Фаза 4 (опционально):** попытка поднять `docker-compose.development.yml`; если поднимется — ручная проверка ключевых потоков (логин, создание группы/потока, редирект, постбек). Если нет — статический анализ остаётся источником.

## Критерии готовности

- Каждая страница фронтенда описана; каждый эндпоинт из роутов задокументирован; каждая модель описана.
- В `05-screen-api-mapping.md` нет экрана без списка вызываемых API и нет API без списка вызывающих экранов (или пометки «вызывается трекером/внешним»).
- Все утверждения прослеживаются к конкретным файлам/строкам кода.

## Риски

- Устаревшие зависимости могут не запуститься — фаза 4 опциональна.
- Дохлые/незаконченные ветки кода — фиксируем как «есть в коде, назначения не ясно», не выбрасываем.
