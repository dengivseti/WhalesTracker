# Дизайн-спецификация: комплект документации для повторения WhalesTracker с нуля

> Дата: 2026-10-09. Статус: утверждён пользователем в сессии мозгового штурма.
> База: ветка `docs/system-documentation`, коммит-базис `3df483e`; существующие документы `docs/01–07`.

## 1. Цель

Создать дополнительные документы, позволяющие повторить проект **с нуля без чтения текущего кода**: поведенческая и визуальная идентичность обязательательна, конкретный технический стек — рекомендация, не требование.

Принцип: поведение и UI — контракт; стек — современный на выбор исполнителя. Каждый новый документ самодостаточен для своего слоя, но ссылается на 01–07 для деталей реализации. Утверждения о текущем поведении снабжаются источником (`файл:строка` кода либо сайт https://whalestracker.netlify.app/).

## 2. Документы (нумерация продолжает существующую)

### 2.1. `docs/08-ui-spec.md` — Визуальная спецификация UI
По каждой из 7 страниц (AuthPage, DashboardPage, StatisticPage, OfferPage, EditPage, SettingsPage, InfoPage):
- каркас структуры (ASCII/wireframe-описание блоков), навигация между страницами;
- все формы: поля, валидация, точные тексты сообщений об ошибках;
- таблицы и их колонки; диалоги, тосты, кнопки — точные копирайты;
- состояния: загрузка / пусто / ошибка;
- палитра и типографика темы Material-UI, поведение при ресайзе.

Источники: `client/` (компоненты, тема, тексты); опционально — сверка со скриншотами живого сайта.

### 2.2. `docs/09-deployment.md` — Развёртывание с нуля
- Полный список env-переменных: назначение, дефолты, где читаются.
- Docker Compose (5 сервисов) и nginx: поведенческое описание (что проксируется, маршруты, раздача статики).
- Инициализация MongoDB/Redis, механика «первый вход = создание админа».
- Порядок запуска, проверка живости, резервное копирование.
- Отдельный блок «миграционный совет»: рекомендуемые современные версии образов/пакетов — не смешивать с описанием «как есть».

### 2.3. `docs/10-e2e-acceptance.md` — E2E-сценарии и приёмочные критерии
- Пользовательские пути end-to-end: создание группы → потоков → фильтров → клик по трекер-ссылке `/{groupName}?q={keyword}` → постбек → появление в статистике.
- curl-примеры с полными запросами/ответами для ключевых эндпоинтов (источник — код; при удачном подъёме Docker верифицируются живым прогоном, иначе пометка «не верифицировано»).
- Чек-лист приёмки: «повторение считается успешным, если …».
- Известные баги «как есть» (4 мёртвых эндпоинта, неинкрементируемые счётчики, утечки объектов ошибок) — с явной пометкой «воспроизводить не нужно / известная проблема» (перечень — 02-api.md и 06-docs-vs-code.md).

### 2.4. `docs/11-glossary.md` — Глоссарий и пользовательская модель
- TDS-термины: группа, поток, фильтр (все 15), типы редиректов (все 18), постбек, статистика, remote и т.п. — выверенные по коду и netlify-докам.
- Модель пользователя: один админ, без ролей; его задачи и типичный workflow.

### 2.5. Обновление `docs/README.md`
Оглавление пополняется пунктами 08–11; добавляется блок «Комплект для повторения с нуля (08–11)» с маршрутом чтения.

## 3. Процесс

1. **4 параллельных read-only субагента на модели `glm-5.3-flash` (z.ai)**:
   - UI-исследователь — `client/`;
   - инфраструктурный — Docker/nginx/env;
   - E2E-составитель — маршруты + трекер + фронтенд-вызовы;
   - глоссарист — netlify-доки + код + 03-domain-tracker.md.
   Каждый возвращает структурированный отчёт с источниками.
2. **Главная сессия** собирает документы; сверяет на противоречия с 01–07 и между новыми; правило устранения дублей: деталь уже описана в 01–07 — ссылка; новый контракт — полный текст.
3. **Каждый документ — отдельный коммит** в feature-ветку (правило проекта: в `master` не коммитить).
4. Опционально: подъём Docker для верификации curl-примеров (при неудаче — примеры из кода с пометкой).

## 4. Критерии готовности

- Каждый документ закрывает свой слой без необходимости читать код.
- Тексты сообщений, env-переменные, колонки таблиц, поля форм — исчерпывающие перечни без «и т.д.».
- Явная сверка: противоречий с 01–07 нет.
- README связывает 08–11 в маршрут повторения с нуля.

## 5. Не входит в объём

- Изменение кода проекта, обновление зависимостей, исправление найденных багов.
- Переписывание/правка уже существующих документов 01–07 (кроме README).
- Спецификация новой архитектуры рерайта (выбор конкретного стека остаётся за будущей командой).
